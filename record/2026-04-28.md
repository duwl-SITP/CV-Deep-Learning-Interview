## 1. SFT

目前常见的大模型是Decoder-Only模型，在Decoder阶段一个词一个词地生成。大模型在Pre-training阶段实际上是以补全句子为目标，并不会问答这种形式。

这种格式的核心在于**模拟多轮对话（Multi-turn Conversation）**。下面的第一个例子中，`user`：代表真实用户，是模型需要响应的对象。 `assistant`：代表模型本身。在 SFT 阶段， `assistant`这部分内容就是**标签（Label）**，模型会被训练去拟合这部分文字。

第二个例子中增加了三个关键角色/字段：

1. **system (系统提示词)**：详细列出了模型可以调用的工具列表（Tools）。这是模型的运行规则。
    
2. **tool_calls (工具调用意图)**： 注意：此时 `assistant` 的 `content` 是空的，取而代之的是一个结构化的指令。这代表模型意识到自己无法直接回答，需要**发起一个请求**。
    
3. **tool (工具返回结果)**： 这是一个特殊的角色。它模拟了外部系统（比如翻译 API 或搜索引擎）返回给模型的数据。模型拿到这个 `content` 后，再进行最后的总结。

``` json
{
    "conversations": [
        {"role": "user", "content": "你好"},
        {"role": "assistant", "content": "你好！"},
        {"role": "user", "content": "再见"},
        {"role": "assistant", "content": "再见！"}
    ]
}
{
    "conversations": [
        {"role": "system", "content": "# Tools ...", "tools": "[...]"},
        {"role": "user", "content": "把'你好世界'翻译成english"},
        {"role": "assistant", "content": "", "tool_calls": "[{\"name\":\"translate_text\",\"arguments\":{\"text\":\"你好世界\",\"target_language\":\"english\"}}]"},
        {"role": "tool", "content": "{\"translated_text\":\"Hello World\"}"},
        {"role": "assistant", "content": "Hello World"}
    ]
}
```

我们将 Prompt 和 Response 拼接在一起作为一个长句子喂给模型。在 SFT 训练中，我们通常**只计算 Response 部分的 Loss**。对于 **Prompt** 部分，我们通过 **Mask（掩码）** 忽略掉它们的损失。

## 2. LoRA

LoRA 基于预训练模型权重矩阵的**低秩假设**，通过将参数更新量 $\Delta W$ 分解为两个低秩矩阵 $A \in \mathbb{R}^{d \times r}$ 和 $B \in \mathbb{R}^{r \times d}$ 的乘积（其中 $r \ll d$ ），实现高效微调。其核心计算公式为：

$$W' = W + \Delta W = W + AB$$

**初始化策略：**

- **矩阵 A** 采用高斯分布初始化，**矩阵 B** 初始化为全 0。
    
- **设计初衷：** 这种非对称初始化确保了在训练初期 $\Delta W = 0$ ，使模型输出与预训练状态保持一致，提升训练稳定性。
    
- **关键约束：** A、B 矩阵不可同时初始化为 0，否则会因**对称性问题**导致神经元无法学习到差异化特征（即梯度对称性无法打破）。

### Q1：LoRA 的秩 $R$ 应该怎么选？

**答案：** 在大多数自然语言任务中， $R$ 取 4、8 或 16 就能达到全量微调 90% 以上的效果。增加 $R$ 虽能提升参数量，但并不总是带来性能线性增长，过大的 $R$ 反而容易导致在小数据集上过拟合。

### Q2：LoRA 在推理（Inference）阶段会有额外延迟吗？

**答案：** **没有额外延迟。** 在部署阶段，我们可以将训练好的低秩矩阵乘积 $AB$ 直接加回到原始权重矩阵 $W$ 中（即 $W_{new} = W + AB$ ），这一过程称为权重合并。合并后的模型结构与原始模型完全一致，因此推理速度和显存占用没有任何变化。

### Q3：LoRA 中的 $\alpha$ 参数（Scaling Factor）是什么作用？

**答案：** $\alpha$ 是一个缩放因子，计算时 $\Delta W$ 会乘以 $\alpha / R$ 。它可以控制LoRA对原始模型权重更新的强度。较大的 $\alpha$ 会使LoRA更新的幅度更大，这意味着模型会更快地适应特定任务，但也可能导致过拟合；较小的 $\alpha$ 会使更新较为温和，有助于模型的稳定性和泛化能力，但可能需要更多的训练步骤才能达到较好的性能。

``` python
class LoRA_Layer(nn.Module):
	def __init__(self, module, r, alpha, std)
		super().__init__()
		
		self.module = module
		self.adapter = nn.Sequential(
			nn.Linear(module.in_features, r, bias=False),
			nn.Linear(r, module.out_features, bias=False),
		)
		
		self.scale = alpha / r
		
		nn.init.normal_(self.adapter[0].weight, std=std)
		nn.init.zeros_(self.adapter[1].weight)
		self.adapter.to(device=module.weight.device,
						dtype=module.weight.dtype)
	
	def forward(self, input):
		return self.module(input) + self.adapter(input) * self.scale
```
