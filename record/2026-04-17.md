## 1. 为什么KVCache的内存管理效率是影响推理系统吞吐量的关键？

当下，主流的大语言模型普遍采用因果解码器（Causal Decoder）架构，其推理过程分为预填充（Prefill）和解码（Decoding）两个阶段。

在**预填充阶段**，推理引擎处理完整的提示词（Prompt）序列，通过单次前向推理生成提示词中所有词元的 KV 缓存，并根据上下文计算产出首个回复词元。此时，提示词对应的 KV 缓存已全量存储于显存中。这一阶段是高度并行的，能够充分利用 GPU 的算力资源，因此属于 **compute-bound（计算受限）**，瓶颈在于算力而非内存。

进入**解码阶段**，系统采取步进式推理：在计算第 $n$ 个回复词元时，模型首先计算当前位置的查询（Query）、键（Key）与值（Value）向量，随后将当前 Query 与已存储的（包含提示词及前 $n-1$ 个回复词元的）KV 缓存进行注意力机制运算，从而预测下一个词元。与此同时，新生成的 Key 和 Value 向量会被增量写入缓存。此过程循环往复，直至模型输出结束符（EOS），标志着解码阶段完成。由于该过程是串行的、难以并行加速，且频繁读写缓存数据，因此整体表现为 **memory-bound（内存受限）**，瓶颈主要在 KV Cache 的存储与访问效率。

## 2. 多头自注意力的计算复杂度

| **阶段**         | **操作内容**                  | **计算量 (FLOPs)**              | **复杂度**        |
| -------------- | ------------------------- | ---------------------------- | -------------- |
| **1. 线性映射**    | 生成 $Q, K, V$ (3次矩阵乘法)     | $3 \times (2Nd^2)$           | $O(Nd^2)$      |
| **2. 得分计算**    | $QK^T$ (1次矩阵乘法)           | $2N^2d$                      | $O(N^2d)$      |
| **3. Softmax** | **指数、求和、除法归一化**           | ** $\approx 3 \times N^2$ ** | ** $O(N^2)$ ** |
| **4. 加权求和**    | $Score \times V$ (1次矩阵乘法) | $2N^2d$                      | $O(N^2d)$      |
