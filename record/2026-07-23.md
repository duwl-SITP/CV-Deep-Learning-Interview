## 1. Verl 中的各种 Batch_size

`data.train_batch_size` 表示外层训练迭代使用多少个原始prompt。

`rollout.n` 每个group的大小。

每个 prompt 的 `rollout.n` 个回答构成一个GRPO group，用于计算组内相对 advantage。总回答数 =  `data.train_batch_size` \* `rollout.n` 。 

`actor.ppo_mini_batch_size` 表示每次 `optimizer.step()` 使用多少个 prompt group。

`actor.ppo_micro_batch_size_per_gpu` 表示每个GPU在一次前向和反向中实际处理的 response 数。

每个 GPU 数据并行 worker 的本地 mini-batch 为：

$$
M_{local} = \frac{actor.ppo\_mini\_batch\_size*rollout.n}{D}
$$

其中，$D$ 为 GPU 数。

梯度累积次数为：

$$
N_{grad\_accumulation} = \frac{actor.ppo\_mini\_batch\_size*rollout.n}{D*actor.ppo\_micro\_batch\_size\_per\_gpu}
$$

`rollout.log_prob_micro_batch_size_per_gpu` 表示计算或重算 rollout/old-policy log probalility时， 每个 worker 一次前向处理多少个 response。

`ref.log_prob_micro_batch_size_per_gpu` 表示 reference model 计算概率时的 per-GPU forward batch。

## 2. Verl 中的混合精度计算

配置文件中设置：

``` yaml
  actor_rollout_ref:
    actor:
      fsdp_config:
        model_dtype: fp32
        mixed_precision:
          param_dtype: float16
          reduce_dtype: fp32
          buffer_dtype: fp32
```

  `model_dtype` 控制 Transformers 模型初始化和主参数保存类型。  对 actor 来说，它也会影响 LoRA 参数类型，因为当前 FSDP engine 会把 LoRA adapter 转换成与 base model 相同的 dtype。

  `mixed_precision.param_dtype` 控制 FSDP 前向/反向期间的参数计算类型。

  `mixed_precision.reduce_dtype` 控制 FSDP 多卡梯度通信/归约的类型。 推荐保持 FP32，因为 FP16 梯度归约更容易：

  - 小梯度下溢；
  - 梯度累加误差变大；
  - 多卡归约产生不稳定。

`mixed_precision.buffer_dtype` 控制模型 buffer 的类型，例如非参数状态。推荐保持 FP32，显存影响通常小于模型权重和激活。
