## 1. DeepSeed-ZeRO-DP

ZeRO 利用数据并行的计算和内存资源，以降低用于模型训练的每个设备（GPU）的内存和计算需求。通过将模型训练中的各种状态（权重、梯度和优化器状态）在分布式训练硬件中的可用设备（GPU 和 CPU）之间进行划分，ZeRO 降低了每个 GPU 的内存消耗。

训练系统的整体内存消耗主要分为两类：

1. 模型状态：对大模型而言，大部分内存由模型状态占据，包括优化器状态（以 Adam 为例，它需要保存两个优化器状态：梯度的时间平均动量和方差，用于计算更新）、梯度和参数； 

2. 残余状态（Residual States）：其余内存由激活值、临时缓冲区和不可用的碎片化内存消耗。

ZeRO-DP包含三个主要优化阶段，对应优化器状态、梯度和参数的切分，并可累积启用：

1. 优化器状态切分 ( $P_{os}$ )：内存降低 4 倍，通信量与数据并行 DP 相同。 

2. 进一步加入梯度切分 ( $P_{os}+g$ )：内存降低 8 倍，通信量仍与数据并行 DP 相同。 

3. 进一步加入参数切分 ( $P_{os}+g+p$ )：内存降低与DP度 $N_d$ 线性相关；例如在 64 块 GPU 上可获得 64 倍内存降低，但通信量 modest 地增加 50%。

### $P_{os}$：优化器状态切分

对于数据并行度 $N_d$，将优化器状态分成 $N_d$ 个相等分区，第 $i$ 个数据并行进程只更新第 $i$ 个分区对应的优化器状态。

因此每个数据并行进程只需保存并更新总优化器状态的 $1/N_d$，并只更新参数的 $1/N_d$。

每个训练 step 结束时，对数据并行进程执行 all-gather，以获得所有进程上的完整更新参数。

内存节省方面，优化器状态切分后内存从 $4\psi + K\psi$ 降为 $4\psi + K\psi/N_d$ 。

### $P_g$：梯度切分

每个数据并行进程只更新自己负责的参数分区，因此只需要这些参数对应的 reduced gradients。**reduced gradients** 可以理解为：多个数据并行进程上的局部梯度经过求和/平均之后得到的全局梯度。

数据并行时，每张 GPU 处理不同的数据，所以每张 GPU 反向传播得到的梯度不同。

假设有 4 张 GPU，它们分别算出某个参数 $\theta$ 的局部梯度：

$$
g_0, g_1, g_2, g_3
$$
​
如果想让 4 张 GPU 等价于用一个更大的 batch 训练，就需要把这些梯度合并：

$$
g = \frac{g_0 + g_1 + g_2 + g_3}{4}
$$
​​
反向传播时，每层梯度一旦可用，就只在负责更新相应参数的进程上执行归约；归约后梯度不再需要，其内存可以释放。这样保存梯度所需内存从 $2\psi$ 降为 $2\psi/N_d$ 。**归约 reduction** 指的是把多个进程/设备上的数据按照某种操作合并成一个结果。常见的归约操作有：求和、均值、最大值、最小值。

从通信操作看，这等价于 Reduce-Scatter：不同参数对应的梯度被归约到不同进程。实践中作者使用 bucketization 策略，把同一分区的梯度装入 bucket，一次性执行归约。这与 NVIDIA AMP 优化器把 all-reduce 梯度分桶以重叠通信和计算的思路类似，但 ZeRO 在分区边界执行 reduction 而非 all-reduce，从 而降低内存并重叠通信与计算。 

内存节省方面，去除梯度和优化器状态冗余后，模型状态内存进一步降到 $2\psi + (2+K)\psi/N_d$，$N_d$ 大时约为 $2\psi$，即约 8 倍降低。

### $P_p$：参数切分 

类似优化器状态和梯度，每个进程只保存自己分区对应的参数。当其余分区的参数在前向和反向传播中需要时，通过负责该分区的进程广播获得。乍看这会带来大量通信，但作者分析表明，它只会把基线 DP 的总通 信量增加到 1.5 倍，同时实现与 $N_d$ 成比例的内存降低。

## 2. Python中等号和is的区别

### \=\=比较值是否相等

``` python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b) # True
```

### is比较是否是同一个对象

``` python
a = [1, 2, 3]
b = [1, 2, 3]

print(a is b)    # False
c = a            # python中赋值是引用
print(c is b)    # True
```
