## 1. MoE

MoE Layer 包含：

$$
\mathrm{MoE}(x) = \sum_{e\in \mathcal T(x)} g_e(x)\mathrm{Expert}_e(x)
$$

- $\mathrm{Expert}$​：第 $e$ 个专家，通常是独立 FFN；
- $g_e(x)$ ：Router 给专家的权重；
- $\mathcal{T}(x)$ ：当前 token 选中的 Top-k 专家集合。

经过 Self-Attention 后得到的特征展平 $X \in R^{N×d}$ 。Router 为每个 token 打分，Router 通常是一个线性层：

$$
Z=XW_r​
$$

第 $i$ 个 token 对第 $e$ 个专家的分数是：

$$
z_{i,e} = x_i^\top w_e​
$$

再通过 Softmax：

$$
p_{i,e} = \frac{\exp(z_{i,e})} {\sum_{j=1}^{E}\exp(z_{i,j})}​
$$

得到该 token 对所有专家的路由概率。

例如：

$$
p_i= [0.05,0.60,0.10,0.20,0.05]
$$

如果使用 Top-2 路由，则选择专家 2 和专家 4。

将 token 分发给不同专家，假设路由结果为：

| Token  | 专家  |
| ------ | --- |
| $x_1$  | 1、3 |
| $x_2$​ | 2、3 |
| $x_3$​ | 1、4 |
| $x_4$​ | 2、4 |

系统会重新排列 token：

$$
\text{Expert 1}: \{x_1,x_3\}, \
\text{Expert 2}: \{x_2,x_4\}, \
\text{Expert 3}: \{x_1,x_2\}, \
\text{Expert 4}: \{x_3,x_4\}
$$

然后每个专家批量计算自己接收到的 token。

这一步称为Dispatch，在分布式 MoE 中，不同专家往往位于不同 GPU 上，所以需要 `all-to-all` 通信：当前 GPU 上的 token→专家所在 GPU。

每个专家执行 FFN，再通过归一化后的权重 $p_{i}$ 对每个专家的输出进行加权求和。

某个 token 只经过被选中的专家，因此该 token 的梯度只更新这些专家。未被选中的专家通常得不到 token 的梯度。所有 token 都选择同一个专家，那么 MoE 就退化成了一个普通 FFN，因此通常加入辅助负载均衡损失。

每个专家通常会设置最大容量，如果某个专家超过容量，超出的 token 可能：

- 被丢弃；
- 转发给次优专家；
- 只走残差连接；
- 发送给共享专家；
- 使用无容量限制的动态调度。
